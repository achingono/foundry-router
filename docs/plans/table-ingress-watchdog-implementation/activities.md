# Watchdog Implementation Activities

## Ordered implementation

1. **Review and freeze scope.** Obtain independent review of this plan and protocol. Record all findings and resolutions before code; preserve the existing uncommitted G1 resume changes and all historical packets/ledgers. First obtain independent review of a design amendment resolving the full-host-suspension guarantee in [protocol](protocol.md#suspension-and-independent-stream-enforcement); no implementation starts until that safety contract is settled. Hash the reviewed plan and selected source baseline. The operator's stage approval does not approve an unprepared infrastructure or paid-execution packet.
2. **Build typed protocol and tests.** Add `scripts/quality/ingress_watchdog/{__init__,schema,signing,errors}.py`. Implement the strict canonical JSON and domain-separated Ed25519 contracts in [protocol.md](protocol.md), including bounded input, exact schema/role keys, duplicate/unknown-field rejection and reproducible cross-process test vectors. Keep the gateway package separate from the production router. Add `tests/unit/test_ingress_watchdog_protocol.py` for malformed/forged/wrong-role/expired/replayed data, ambiguity and privacy; no real keys.
3. **Implement clocks and ledger.** Add `clock.py` and `ledger.py` behind injected interfaces. Implement conservative `CLOCK_BOOTTIME`/trusted-UTC checks and health freshness; refuse unsupported hosts/clock anomalies in the real adapter. Add a fake create-only ledger plus a single-attempt Azure Blob managed-identity adapter; declare `azure-storage-blob` and `h11` as explicitly bounded optional operator dependencies, verifying compatibility rather than changing the production image by default. Enforce the independently attested locked-policy retention of at least eight days and packet validity at most 30 minutes; test short/unverifiable retention, denied overwrite/delete, expiration, duplicate/conflicting/ambiguous writes, lost acknowledgements, concurrent create, SDK retry disabling, policy attestation failure, host suspension and forward/backward clock changes. A fake or Azurite pass is not locked-WORM Azure evidence.
4. **Implement the gateway state machine.** Add `state.py` with explicit `CLOSED`, `ARMED`, `ACTIVE`, `CASE_PENDING`, `CLOSING`, and `DENY_PROBES` phases; no restart restores an active phase. Protect all phase transitions and upstream initiation with one local lock. Consume `arm`, each dispatch, advancement, close and probe in the specified order. A close wins over any pending ledger operation; a late successful dispatch insert consumes the slot without sending. On any uncertain state, close permanently and stop; never start a fresh session as an automatic recovery. Add deterministic interleaving/model tests covering arm races, duplicate slots, stale receipts, blocked writes, expiry/close ordering and restart.
5. **Implement separate proxy and control processes.** Add `proxy.py`, `control.py`, `transport.py`, and `__main__.py`. Use independently authenticated TLS endpoints, fixed-origin upstream TLS, `h11` parsing, bounded request buffers and streaming response pass-through as specified. IPC is Unix-domain with restrictive permissions and verified peer identity. Proxy owns the lease timer and actively aborts all upstream/downstream streams on expiry even if control dies or the stream is idle; a live watchdog kills a SIGSTOPped proxy. Emit sanitized expiry/health events to an independent durable sink without blocking closure. Shutdown/control loss defaults closed. Test hostile HTTP framing, path/host/header manipulation, bad certificate/identity, DNS/redirect/proxy bypass, connection races, queued TLS bytes, stalled event loops, active and idle SSE, backpressure, timeout and redaction. Demonstrate actual first-write ordering is nonblocking and bounded; if the chosen Python/TLS transport cannot satisfy it, stop for an independent amendment rather than weaken the contract.
6. **Implement supervisor.** Add `supervisor.py`: one-shot launch under a distinct runner UID/GID; drop child privileges/capabilities, close descriptors, isolate keys and network, and enforce `no_new_privs`/ptrace protection as in the protocol. Verify original PID, start identity and live state synchronously after sampling trusted time; heartbeat using a separate credential with single-use challenges; stop renewal/close on child exit, supervisor failure or uncertainty. Never pass renewal credentials or privileged environment to child/helpers. Tests use real Linux subprocesses to attempt runner access to supervisor keys, memory, file descriptors and identity tokens; SIGTERM/SIGKILL runner, supervisor or both; and inject delayed/replayed messages, PID reuse/zombies and clock uncertainty. Confirm the applicable TTL-plus-approved-clock-error bound and signed hard deadline; a hung but live child may renew to hard deadline only.
7. **Implement verifier and receipts.** Add `verifier.py` and `evidence.py` as independent-operator tools, not spawned by runner. Refactor/reuse only pure G1 accounting helpers after review; never import privileged secret-resolving or exec actions into the runner. Independently authenticate a gateway-produced response witness for real upstream HTTP status, terminal usage and clean EOF; reject runner-provided artifacts as proof. Bind signed initial baseline, pre-dispatch snapshot, prior settlement and advancement receipts to session/slot/dispatch hash/config/process/finance and short freshness. Establish the protocol's enforced no-mutation boundary: no external writers, pinned sole app writer, zero pending ownership/reservations, proven quiescent reconciliation/reaper and no cycle rollover through forwarding initiation. Analyze current runtime and fault-test concurrent reaper, reconciliation, external write and rollover; if enforcement cannot be proven, block and obtain a separate design amendment. Test stale, mismatched, forged, duplicated, delayed and reordered receipts; forged runner evidence and any state drift must never advance. Resolve the trusted operator's actual diagnostic method and privileges in the separate Azure feasibility packet.
8. **Implement a new fresh G1 harness.** Add `scripts/quality/table_watchdog_g1.py` and `tests/unit/test_table_watchdog_g1.py` without changing the existing resume runner. Prepare fresh private owner-only artifacts; bind an exact matrix of two distinct physical deployments × nonstream/stream, two singleton Azure pools, effective Table mode/table identity/scoped writer, current image/settings, seeds, pricing and evidence. Freeze and independently inventory prior ledgers/liabilities; a budget authority signs a program-wide allocation manifest binding one session and four ordered slots. Atomically consume a deterministic WORM program key and allocation-scoped slot markers shared across hosts as specified in the protocol; use separate budget retention through the funding cycle/audit period and hold until all liability is resolved. Local locks are insufficient. Before dispatch, prove the default 64-input/128-output ceiling including provider overhead or obtain a separately reviewed higher conservative reserve within the same aggregate budget; post-response usage is not pre-dispatch proof. Consume budget slot before session dispatch, retain full liability on ambiguity and halt remaining cases on failure. Test competing sessions/hosts/authorities, expiry, premature hold clearance and incomplete prior histories. Never assert unverified model mappings or free token-counting services.
9. **Implement DENY/restart evidence.** Add `probes.py`: pre-DENY pinned-origin TLS 200; one-way close; durable DENY, restart and two distinct probe markers; and signed origin/independent restart attestations. Use a diagnostic-only phase with separate bounded probe authorizations inside the absolute packet deadline, never the normal forwarding lease. Each post-DENY probe must independently show pinned-origin TLS 403, calibrated ingress-denial details, zero upstream attempts, complete app-log absence and fresh ARM state. The trusted operator performs the one reviewed DENY and restart only after their respective consumed markers and preconditions. Require changed actual process, readiness, unchanged persisted accounts and separately verified post-restart proof before a pass. Missing/delayed logs, proxy/app 403, network failures, uncertain marker/restart or unverifiable app-log completeness block without retry. Mock crashes before/after every mutation, correlation, timeout and restart ordering.
10. **Verification and documentation.** Add focused unit and real-local TLS/SSE integration tests, then run full `.venv` suite, minimum 80% coverage on implemented code including the new operator package, Ruff lint/format, Mypy, applicable local packaging/Docker build, and conditional SonarQube scan. Run the repository deep-review prompt in a separate session and address all Critical/Major findings. Verify relative links, secrets/redaction and final diff; document only actual results and any unavailable gates. Update operational/security/traceability docs if implementation changes behavior or status. No local test is presented as Azure proof.
11. **Future Azure feasibility, not part of this plan-writing request.** Produce a separate reviewed finite what-if and cost/permission/network packet for the isolated internal ACA environment, VNet/subnets/private DNS, gateway VM, immutable Blob ledger, diagnostics and managed identity. Bind access/egress, WORM retention/lifecycle, trusted time source, independent verifier and operator roles; account for locked-policy deletion constraints and privilege boundaries. In a non-paid disposable setup verify effective roles, no-bypass attempts, actual first-write/expiry/fault behavior, calibrated ingress-vs-app 403 logs and clock bounds. Fail closed and preserve evidence on any uncertainty; no paid provider traffic.
12. **Future exact G1 gate.** Only after all previous gates, separately prepare and independently approve a fresh private signed four-case packet and budget accounting for consumed prior liabilities within applicable USD 1 / 16-attempt limits. Bind all hashes, real costs, sole writer, two singleton Azure pools, probe scope, identity and timings. This plan authorizes no resource mutation, case dispatch, old case-3 reuse or production cut-over.

## Verification matrix

| Boundary | Required negative and positive tests |
|---|---|
| Authorization | Wrong reviewer/verifier/runner role, certificate, signature, packet, route, model, body, deadline, and oversized/ambiguous HTTP all refuse; valid signed exact request enters the intended phase. |
| Ledger and crash | Every write conflict/timeout/lost acknowledgement closes; concurrent create and rearm after restart never grant a second slot; late insert cannot emit an upstream byte. |
| Liveness | Test SIGTERM/SIGKILL, control disconnect, delayed/replayed heartbeat, PID reuse, stale or untrusted clock and hard deadline. Test host suspension separately against the independently amended failure contract; do not presume bounded socket closure while the whole host is suspended. |
| Financial continuity | Every initial and per-case snapshot proves sole writer and exact account/counter/cycle state; stale/forged/late receipts and all drift refuse before dispatch; each failed case halts the rest. |
| Transport | Fixed origin/TLS/peer identity, no retry/redirect, bounded framing and memory, idle/active SSE cancellation, no retries after output, and no sensitive logs. |
| Provider attempt bound | Zero retry plus singleton pools are verified and mocked 429/5xx/transport failures cause at most one physical backend attempt per case. |
| Final proof | Correctly attributed pre- and post-restart ACA denial plus fresh ARM state; simulated app/proxy 403, missing logs, restart failure or ambiguous probe never pass. |
| Azure feasibility | Real dedicated network/role/WORM/time/diagnostic checks are separate, non-paid and independently reviewed; inability to prove any property blocks G1. |
