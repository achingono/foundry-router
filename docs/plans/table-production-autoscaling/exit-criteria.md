Each gate is sequential for its dependent actions. Table/one may be deployed and closed as an intermediate outcome while payload/scale gates remain open. None of these execution gates has passed in this planner session.

## Gate Checklist

### G0 — Reviewed/current prerequisites

- [ ] Independent plan approval; one writer and USER WORK preservation recorded.
- [ ] Current source/effective live baseline/discovery verified; missing captures regenerated only through a new reviewed run.
- [ ] Candidate focused/full `.venv` tests and ≥80% coverage, lint/format/mypy, applicable Docker/Azurite/Bicep checks pass; exact skipped/unavailable gates disclosed.
- [ ] Conditional Sonar checked (absent N/A) and independent deep review clear all Critical/Major.
- [ ] Exact isolated executable/identity/configuration/image/budget packet independently approved before any mutation or inference.

### G1 — Fresh isolated current-release Table acceptance

- [ ] Existing resources reused or concrete minimal fresh-table/resource proposal reviewed; managed identity has scoped table access and parent settings unchanged.
- [ ] Four fresh cases (two Azure deployments × nonstream/stream) return200/completed with verified usage, exactly matched local estimate debit, counter deltas and zero reservations/inflight after each.
- [ ] Actual isolated restart verified through changed identity/count, readiness and unchanged persisted balances/counters/configuration; no extra restart inference.
- [ ] USD 1/16-attempt fresh aggregate allocations enforced, ambiguity retained, old original/supplemental ledgers untouched. Current Azure-account coverage is explicitly named privately and summarized without fabricated coverage.

### G2 — Production Table/one migration and restoration

- [ ] Exact migration packet and minimal what-if independently approved; current original ingress/secret/configuration hashes bound.
- [ ] Public fence proved, intake/forwarding/background writers drained; fresh same-process four-account snapshot captured at quietness.
- [ ] Counter initialization/continuity decision resolved and tested; seed estimates conservative and no allowance/refund duplication.
- [ ] Old memory writer frozen and all replicas absent before successor; owned Table partitions seeded exactly once with canonical four-account ownership, correct cycles/reserves and snapshot binding.
- [ ] Sole healthy single-worker **Table/max1** successor; unchanged22backends/14pools/aliases/prices/provider settings unless refreshed baseline proves authorized changes; no non-Azure live calls.
- [ ] Scoped Azure production acceptance passes financial settlement/cleanup; unsupported/excluded operations honestly recorded and reviewer accepts exact migration coverage.
- [ ] Quiet actual production restart preserves all four account balances/debit/recovery counters without initial seed reload; no unexplained reservations.
- [ ] Exact original ingress restored and verified with sole healthy writer/public readiness. Any failure has an independently reviewed fresh-state recovery, never stale memory reactivation.

### G3 — Supported Azure payload/resource contract

- [ ] Source-backed operation matrix covers Azure Responses, embeddings, Foundry Anthropic and MAI, content versus wire/context/output units; unknown wire limits explicitly upstream-owned.
- [ ] No router size cap below supported upstream sizes for supported operations; no blind512MiB/global-cap change or unbounded-buffering `None` mode. Unknown architecture decision resolved before deployment claims.
- [ ] Model-last/chunked/unknown-length intake safe before provider resolution; non-Azure caps/capabilities/configuration behavior preserved by regression tests.
- [ ] Estimator size/serialization follows accepted operation policy without financial regression; depth/auth/time/redaction/security and SSE/no-post-output-retry protections preserved.
- [ ] Synthetic realistic supported-content boundaries and concurrent workloads prove peak aggregate memory≤70% of selected supported static allocation, responsive readiness, bounded overload and no OOM/resource leak; static CPU/memory and capacity parameters independently reviewed.

### G4 — Shared admission and operational visibility

- [ ] Azure quota grouping/actual limits/window/token semantics verified by source and actual deployed admission; no inferred Pacific RPD/byte-token rules.
- [ ] Current-release actual two-worker/replica quota+credit admission/settlement/persistence and shared health visibility verified; injected 429/5xx tests separately labeled; no deliberate provider overload.
- [ ] Preserved non-Azure providers demonstrably safe under whole-app scaling without unauthorized semantics/configuration changes; otherwise max1 remains a blocker.
- [ ] ETag conflicts/lost acknowledgements/storage outage/reaper/scale-transition uncertainty fail closed and retain conservative charges.
- [ ] Actual OTLP aggregation or independently reviewed verified operational alternative covers traffic/admission/error/latency/resources/restarts; shared ledger/quota views nonadditive and local metrics labeled local.

### G5 — Bounded horizontal scale acceptance and final handoff

- [ ] Exact resource/scale packet reviewed after current full verification; supported static sizing, concrete HTTP/KEDA threshold/stabilization, min1/max2→max3 and region-specific cost estimate bound.
- [ ] Time-limited≤30-minute synthetic/no-paid-loop exercise proves actual1→2→3→1 transitions and designed memory/readiness/overload behavior.
- [ ] Fresh bounded small paid Azure calls prove shared admission/settlement on at least two actual workers within remaining program slots; configured replica count alone is insufficient.
- [ ] SSE and financial persistence survive scale-down/restart with no duplicate debit, seed replay, refund or unsafe overlap. Failure falls back to Table/one without resetting durable state.
- [ ] Canonical operational/API/configuration/security/architecture docs and traceability reflect measured status; relative links/final diff/secrets check and independent final review pass.
