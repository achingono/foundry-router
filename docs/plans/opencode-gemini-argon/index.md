# Gemini 4 Argon through OpenCode

Status: **Planned** (independent plan review approved implementation). October 13, 2026. User requested Gemini 4 Argon production deployment through OpenCode, and asked why Sonnet 5.5 is absent. Sonnet was not in the [last production release](../openrouter-production-two/deployment-evidence.md); no Sonnet-specific rejection is recorded. This scope does not add Sonnet.

## Contract

Add explicit `opencode_google` provider at the existing backend/API/forwarding boundaries. Existing `opencode_zen` continues its Responses wire. OpenCode's [current model documentation](https://opencode.ai/v2/docs/console/models/) advertises `gemini-4-argon` at `https://opencode.ai/inference/v1/models/gemini-4-argon`, using the Google SDK. Both the legacy `/zen/v1/models` catalog and current `/inference/v1/models` advertise the exact ID. Catalog presence is not live inference evidence.

Require HTTPS API root, safe raw path (no encoded/dot/duplicate segments, operation suffix, userinfo/query/fragment), and bounded physical deployment matching `[A-Za-z0-9][A-Za-z0-9._-]*` (maximum 512 bytes). Do not restrict arbitrary backend counts or encode a model allow-list. Require native surface, Responses only, metered credit, and a text-only Google profile with explicit `native_thinking_level: low` or `minimal`, `thought_token_pricing: true`, and no tools/media/continuation. Existing validated Google native adapter handles bounded text histories, native usage (including thought tokens), output signatures, and SSE lifecycle; choose it for this provider without permitting other Google feature profiles. No public raw Google fields, tools, stored continuation, or provider routing extras.

Transport appends `/models/{deployment}:generateContent` or `:streamGenerateContent?alt=sse` to the exact root. Supply server-owned Bearer authentication, strip all caller credentials, disable redirects, and preserve origin/base-path confinement. Do not insert a body `model`, Google service `/v1beta` suffix, or Azure version. Reuse translated single-shot forwarding: pre-output 429 alone allows newly admitted failover; ambiguous dispatched errors charge usage/full estimate; 401/403 enter backend cooldown. No free-tier Google 5xx retry, credential cycling, or failover after emitted events.

Add model-agnostic offline tests for URL/auth/body confinement, admission restrictions, native nonstream/stream translation and thought settlement, single-shot 5xx and 429 policy. Maintain coverage >=80%; focused then full suite, lint/format/types, applicable Docker build, conditional Sonar script and independent contextual deep review. Update canonical configuration, operations and requirements traceability with exact verification scope.

Independent [plan review](review.md) approved implementation with no Critical/Major findings. Argon acceptance binds `thinkingLevel: low` (Google documents low/medium/high); the generic provider may use minimal only for a compatible operator-selected model.

## Production contract

Separate logical pool `gemini-4-argon-zen`, physical model `gemini-4-argon`, one OpenCode backend, and account-owned metered credit group. Current advertised promotional USD/M input/output price is 2/10 (regular 4/20); use conservative regular 4/20 estimates pending verified account pricing. No authoritative provider balance claim. Keep existing pools, aliases, memberships, prices, authentication and ingress; memory state, one worker, max one replica. No new infrastructure. User must confirm closed intake for drain/restart and fresh OpenCode allocation/reserve; reconcile all existing account estimates after quiescence. Never duplicate an account allocation in concurrent staging and production writers.

Use four new one-shot durable acceptance slots, each maximum 128 output tokens / 120 seconds, fixed synthetic non-sensitive text: isolated staging nonstream then stream; production nonstream then stream. Bind slots to immutable image/config/model/request hashes; require meaningful text, complete terminal evidence, thought-inclusive usage/debit and zero residual reservations. Thinking-only or truncated output does not pass. Reserve each slot before egress, forbid replay, halt on failure/ambiguity, retain consumed-slot/usage/settlement evidence without prompts, outputs or secrets. Staging budget belongs to the same account; transfer a fresh conservative remaining estimate after fully stopping its writer. Existing staging app must stay stopped unless a separate fresh all-account allocation is reviewed. A local isolated app is preferred for staging to avoid stale account seeds. Production rollout requires immutable tested image digest, coherent pinned secrets and current all-account credit seed, stopped old writer and zero active/inflight reservations. Capture reviewable rollback bindings; rollback also requires fresh balances. No rollout until independent plan/implementation review and exact staging success. If required account/maintenance inputs remain missing, deliver the verified implementation and concrete deployment packet with the remaining gates recorded.
